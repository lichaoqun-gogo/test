## 二、测试用例

### 测试用例 1：引入申请 - 普通用户发起（经过所有节点）

**场景描述**：技术研发部的普通用户张三发起引入申请，需要经过完整的4个审批节点。

**前置条件**：
- 申请人：user100（张三，技术研发部）
- 项目运维部门：运维部
- 业务类型：introduce（引入申请）

**预期审批链路**：
```
Node 0: 发起节点（张三）
  ↓
Node 1: 本部门开源治理专员复审（李四，技术研发部专员）
  ↓
Node 2: 使用部门确认（跳过，因为引入申请不需要）
  ↓
Node 3: 管理部门评审（孙八，开源治理办公室）
```

**测试步骤**：

| 步骤 | 操作人 | 操作 | 请求 | 预期结果 |
|------|--------|------|------|----------|
| 1 | user100 | 创建任务 | `POST /api/v1/tasks` | 任务创建成功，状态=draft |
| 2 | user100 | 提交任务 | `POST /api/v1/workflow/tasks/{id}/submit` | 状态=approving，当前节点=Node 1（李四） |
| 3 | user001 | 审批通过 | `POST /api/v1/workflow/tasks/{id}/approve` | Node 1通过，流转到Node 3（孙八） |
| 4 | user010 | 审批通过 | `POST /api/v1/workflow/tasks/{id}/approve` | Node 3通过，状态=approved |
| 5 | - | 查询审批历史 | `GET /api/v1/workflow/tasks/{id}/history` | 返回4条记录（创建、提交、2次审批） |

**验证点**：
- Node 2 被跳过（原因：引入申请不需要使用部门确认）
- 每个节点的审批人、审批时间、审批意见都有记录
- 最终状态为 approved
